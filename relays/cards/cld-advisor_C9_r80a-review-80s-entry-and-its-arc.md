## 3. How it could come out wrong, written before any run

1. **The form asks for judgements that are main's and that the folder does not give.** Which of Review 79's
   eighteen items are resolved; what moved towards the goal; what each navigation page should now say; whether
   anything is promoted. Where main's record does not settle one, this seat does not settle it: the item is carried
   with that reason, or the line says that it was not assessed, and the note names it.
2. **A count comes out other than main's.** Then it is not repaired. The item stops, and the command and its output
   go back to main.
3. **The entry says "checked" where the table does not.** The second table gives "not checked" for 17 of its 57
   rows and for a part of 3 more, counted by this seat before this card. The lock counts the rows by what the table
   says of each, so that the entry's numbers are the table's.
4. **Runs this seat may not be able to make.** The review's tool clones a commit and runs the gates and the belt
   there; the full suite takes hours on this machine; one line of Review 79's entry was checked against main's
   private log, which this seat does not have. Each line says what was run, where, and what was not.
5. **A check of main's needs what this clone does not hold:** a reader's commit, a session's branch that is read
   through a mask, a package that is not installed. The lock then says aloud that it did not run that check, and
   holds the committed output.
6. **The readers' files are on branches this seat is told not to read.** agy-exp's findings are given in main's words
   "so that its lane need not be read". The arc cites each file by its path and commit as main's record gives them,
   and this seat opens no lane that is read through a mask.
7. **The patch is built on a head that moves.** Main lands nothing until the review is entered, but the views are
   generated from the tree: a patch that carries generated pages can conflict with a commit of main's made after
   `10fbbc1c2`. The note says which files are generated, so that main can generate them again.
8. **Main's draft is marked as a draft.** The first table's heading says that two of four files were in when it was
   written. It is kept as written, and the note says so.

## 4. What it rests on, and what it must not touch

- It rests on main's `10fbbc1c2`, and on main's folder as it stands there.
- It changes no statement of the mathematics and no number. It changes no sealed file and no file that a list of
  hashes names.
- It quotes nothing the owner said, and names no session as an authority.
- It mends nothing: a finding that waits is said to wait.
- It writes to this seat's branch only. The patch is main's to apply.

## 5. One control that must fail if the work is broken

The arc's lock must fail when one row of either table is deleted, when a row's state is changed from "not checked"
to "held", and when the entry's count of findings is changed by one. And the gate on a review's action items must
fail on the patch with one of Review 79's items left open.
