# cld-advisor · C2 · WP-0.7, series 4: the six cases the suite lists as manual

*A card inside the package main proposed on this seat's page (WP-0.7). Committed before any mend of the series.*

## 1. The package and the question

WP-0.7, enforcement. The planted suite plants 21 cases by itself and lists six as manual. Three of the six main has
mended (PV5, PV7, PV25): are they caught by a gate when the suite plants them on the real pages? Three are open: can
each be mended as a function of the commit — a negative worded about the object that passes when an old line is
reworded in the same commit (PV23), a lock that compares a printed float as text (PV26), a test run that writes a
tracked file (PV27)?

## 2. What is delivered, and what done means

| | |

## 3. How it could come out wrong, written before any run

1. **PV27 may not be a gate's to catch.** A gate reads. Whether a test run changes a tracked file is seen by a run. It
   may end as a check in the suite's own harness, the tree compared before and after, or as a read of the tests for
   a write to a tracked path, which is weaker. The seat will say which it built and why.
2. **PV26 may reach only the plain forms.** Whether a string that a lock compares is a printed float is not in the
   lock; it is in the transcript the lock reads. The gate may refuse the forms it can read and count the rest. Two
   instances stand on main and fail on this seat's machine: they are held by name, or are main's to mend.
3. **PV23's mend may need the member-scope baseline by name and not by count,** as series 2 did for two other
   baselines. If the lines carry nothing to key them by, the mend may be weaker: a line that changes is a line that
   left.
4. **PV5, PV7 and PV25 may pass as the suite plants them,** though main's own tests of them pass: the suite plants on
   the real pages. Each one that passes is a finding and a patch.
5. **The count of manual cases is not reconciled with main,** which counts four manual and three with no gate. It is
   reconciled in the series' note.
6. **Main's tests may find what this seat's do not,** as in series 1 and series 3. They are run at the base and on
   the whole series before anything is called green.
7. **The seat's own variants may find a further form of a case,** as the last variant of series 3 did. It is then
   mended in the series and said.

## 4. What it rests on, and what it must not touch

- It rests on series 1 as landed and on series 2 and 3 as sent. If main changes either, it is rebuilt on what main
  lands.
- It changes no sealed file, no ledger row and no page of main's record.
- It changes none of main's tests without a dated note in the test.
- It writes to this seat's branch only.

## 5. One control that must fail if the work is broken

The suite's five controls must be caught on the end of the series. Each of the six new plants has a control of its
own: the same plant with the violation taken out must pass. And each case must be NOT caught on the commit before its
mend: if it is caught there, the patch mends nothing and is not sent.

Nothing to start. If PV27 ends in the suite's harness and not in a gate, main's word on where it belongs.
