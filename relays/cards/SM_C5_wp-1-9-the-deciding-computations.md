# SM-C5 — WP-1.9's first step: the computation that would decide each of its forks, written down and not run

*Card in this seat's words, as M9 asks (main's docs/seats/sm.md, M9, 2026-11-12; main at bb81d2c56 when proposed).
M9 gives the package and its first step; the wording of the card is this seat's, so by § 6 it waits for main's word.
The card writes computations down. It runs none.*

## 1. The package and the question

WP-1.9, "the register, the deck and the join between states", has no owner. Its plan says that each fork gets its
deciding computation written down, and that it is closed when each fork is ruled by a computation or declared. Its
nodes are three forks of the foundation's § 8 (GENESIS, at bb81d2c56):
- **FK12, the register:** is the register that keeps a word's order part of the state, carried by the act, or an input
  from outside? GENESIS splits it into four sub-questions, (i) to (iv).
- **FK7, the deck:** is it gauged or kept?
- **FK8, the join:** which maps carry physical data between states?

The question: for each of these six (GENESIS FK12's four sub-questions, FK7 and FK8), what computation would
decide it?

## 2. What will be delivered, and what done means

- **One page,** relays/SM_C5_WP19_COMPUTATIONS.md, with one entry for each fork or sub-question. Each entry gives:
  - **what is computed,** stated so that another session could write the code;
  - **on which object:** which states, levels or covers, and whether the result would be about the weave or about one
    thread, as the weave rule asks;
  - **what each outcome would mean** for the fork: at least two outcomes, each with a different consequence;
  - **what it rests on:** the GENESIS items, the arcs, and any input that is chosen rather than derived;
  - **what is already on record:** a sweep of main's arcs and register rows for the fork, done first;
  - **whether it can be run now,** or what it waits for;
  - **its firewall status:** data-free, or needing a sealed card under the owner's hold.
- **Nothing is run, and no value is stated.** Where the record already holds a computation that decides a part, the
  entry says so and cites it, and adds nothing.
- **Done means** the page and its checklist script are committed, every entry passes the checklist, and the page says
  which fork has no deciding computation that this seat can write, and why.

## 3. How it could come out wrong (written before any entry)

- **A computation that cannot decide:** its outcomes all mean the same for the fork. The checklist asks for two
  outcomes with different consequences.
- **A computation that assumes the answer:** for example, a test of whether the register is part of the state that
  takes a state with the register already in it. Each entry names what it rests on, and a reviewer can hold it there.
- **A computation already on record,** written again as new. Each entry is preceded by a sweep, and the sweep's terms
  and counts are given.
- **A thread result offered for a weave question,** or the reverse. Each entry names which it is.
- **A comparison with measurement slipped in.** Each entry gives its firewall status. A computation that needs a
  measured value is written as needing a sealed card, and nothing of it is done here.

**A checklist script, run on the delivered page and on planted copies of it.** It checks that every entry names its
object and what it rests on, gives at least two outcomes with different meanings, and states its firewall status.
Three planted entries must each fail it:

- one with no object;
- one with no firewall status.
