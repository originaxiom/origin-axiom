## REFUTED — the c-exclusion. chat1 reasoned about c, not about c's SHADOW.

chat1: *"c ≡ γ₃ is complex conjugation on the 27 — which is exactly τ … But τ is

> *"The 27-shadow map is banked: σ₋₁ → D (12 flips), σ_χ₋ → D₂ (the ELEVEN),
> **σ_c → D_c (12)** — K4's frame-invisible legs are **27-VISIBLE**."*

flips in the 27 is exactly **operand**-type data — the kind of thing that lives in
`T_ad[2] = Hom(Q, μ₂)`. **The type argument is refuted by the banked artifact it
had to survive.**

**And the sealed cell says so in its own method:** *"B939's shadow map σ₋₁→D,
σ_χ₋→D₂, σ_c→D_c … compute the H¹ class of each torsor generator's shadow —
coboundary (trivial class) or **which nonzero class**."* **The cell already
anticipates that a shadow may be a nonzero class.** chat1's argument would make
that branch of the sealed cell unreachable a priori, which a pre-compute argument
is not entitled to do.

**What survives of chat1's point:** `D_c`'s H¹ class **may still be trivial** — a
coboundary. **But that is the computation, not an exclusion.** chat1 removed c by
type; c is not removable by type.
