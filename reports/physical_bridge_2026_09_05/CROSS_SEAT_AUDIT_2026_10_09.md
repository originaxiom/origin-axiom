## Decision rule

At each scientific packet boundary, fetch all advertised heads and read
new relays. Prioritize any negative that would stop a live route, then
positive claims that would become a dependency. Track other intake as
unverified rather than implying that every commit has been audited.
An important new dependency is audited before use, not after the next
routine refresh. This is active-work cadence, not an unattended monitor.

For each load-bearing claim:

1. Pin the author commit, exact claim, claimed population, assumptions,
   producer, inputs, seal and outputs. Read the full findings, subsequent
   corrections and dependency code, not only the headline or test count.
2. Check prior work on all fetched branches before accepting an absence
   or repeating a claimed exclusion. Use the already-banked and absence
   instruments where required; disclose search terms and scope.
3. Separate theorem, finite enumeration, sampling, floating-point evidence,
   conditional model and physical identification. Verify that the claimed
   population and operator/domain match the actual calculation.
4. Inspect scripts for early exits, omitted cases, overwritten outputs,
   stale caches, unused seeds, hard-coded answers, rank thresholds,
   rounding, field/characteristic changes, basis/sign conventions and
   discarded conjugate, boundary or continuum sectors. Inspect the tests
   themselves: saved-output assertions are not producer reproduction.
5. Preregister the discriminating audit before running it. Replay pinned
   producers in an isolated location so original outputs remain intact.
   Retain commands, environment, stdout/stderr, exit status and hashes;
   preserve failures and reseal corrections before rerunning.
6. Use a different derivation or algorithm for the load-bearing fact,
   with known-positive recovery and a genuine opposing/failure control.
   Check numerical stability or exact certificates as appropriate. A
   same-author second implementation is not independent outside review.
7. Audit the inference as well as the numbers. A correct local negative
   cannot close a larger family, different action, changed end/domain or
   the entire generated architecture. Preserve every surviving positive
   and state exactly what would evade the tested obstruction.
8. Publish corrections and requests in a sender-owned relay. Propagate
   accepted corrections into affected local reports and navigation pages;
   request the author to correct their own surfaces. Do not assume receipt
   or scientific acceptance from a push alone. Apply this to our work too.

Evidence labels are separate: READ / REPRODUCED / DIFFERENT-METHOD CHECKED /
OUTSIDE REVIEWED. None alone says the mathematical claim is a derived
physical spectrum. A concern awaiting its discriminating test remains a
concern, not a refutation. A verified negative is retained at its earned
scope; no preference for a positive answer can override it.
