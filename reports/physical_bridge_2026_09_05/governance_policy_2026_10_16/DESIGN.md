# Evidence preserving governance clarification

The owner explicitly approved this enforcement-policy change on October 16:
distinguish preregistrations from pinned source/data, recognize only verified
literal Git-reference provenance, and retain historical design violations
without retroactive compliance. This is maintenance, not new mathematics.

BANKED IDENTITY: preserve the attribution baseline, every existing seal row,
all seven flagged artifacts and the earlier full failure captures byte for
byte. A historical design missing either required literal field remains
noncompliant. Unknown roles fail. The actual scientific producers, parameters,
operators and tolerances are outside the edit set.

PRIOR ART: WORKING_RULES and PRACTICES seal-provenance/attribution rules,
the complete two gate implementations, the full 647-path/6174-row inventory,
all seven attribution contexts, and the five previously reviewed historical
design cases have been read. The earlier targeted governance-review relay
requests exactly this policy decision. No absent-result claim is made.

## Scope and tests before acceptance

Implement explicit, versioned, hash-bound role records. A non-design role
requires an actual source-pin manifest containing the same path and digest;
the role is a review judgment, not inferred from the extension. Recognizable
design/preregistration names or design declarations cannot be relabeled as
source/data. All preregistrations still require both literal fields. Explicit
historical-violation records retain a failing verdict. Missing, malformed,
duplicate, stale or unknown records must not disappear into success.

The attribution exception applies to exact byte ranges in exact pinned files,
not a directory or a larger frozen token budget. Each range must contain a
valid Git reference and a token hit, and its recorded commit must be a real
commit object. A pinned evidence passage must contain that reference and the
same commit (or a uniquely resolvable captured abbreviation). A name-only
old capture without this evidence remains unresolved. Uncovered attribution
outside accepted ranges still reaches the unchanged baseline ratchet.

Use synthetic positive and rejecting fixtures for: missing/malformed policy;
unknown role; changed source/evidence hash; duplicate role; absent manifest
pin; design disguised as code/data; missing design fields; historical
violation; changed reference bytes; absent/fake commit; invalid or overlapping
range; surrounding author credit; and an extra token beyond the exact range.
The integration tests must execute the actual gate entry points on isolated
temporary repositories, not merely compare transcript strings.

Initial adoption is deliberately partial: register only personally reviewed
roles and ref contexts with sufficient pinned evidence. Publish all remaining
unknown/historical failures. A reduced failure population is not completion
of the governance campaign, and an acknowledged historical violation is not
a passing preregistration.

## Execution and custody

Commit this design before implementation. Commit and publish the implemented
source/tests and their metadata pins before the first test execution. Run the
focused maintenance tests, then the complete governance precheck after staging;
keep tracked content and the index quiescent during each certified run. Save
complete output, exit code, duration, source pins and before/after inventory.
No new scientific experiment resumes on the strength of this policy edit.
Report test failures without changing the criterion; repairs get a separate
dated record and the original capture remains.
